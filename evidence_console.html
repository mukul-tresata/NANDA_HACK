Reference Architecture ◆MODEL OVERVIEW

How CEO-Delta plans, measures, and repairs

The mental model behind the five claims below — the shared coordinate system, the run pipeline, the module map, and the design decisions that separate this from an LLM in a loop.

Say this first · ~30 seconds

“Most agent systems plan by asking an LLM to think harder and hoping the plan is good. There's no notion of what a good plan even is, so there's nothing to measure, nothing to improve, and nothing to reuse. CEO-Delta starts from a different place: it treats task structure as a measurable quantity. It figures out what shape a task requires, measures how far the plan it built deviates from that shape, and repairs the plan with graph surgery under a guarantee that it can never make things worse. And because the measurement lives in a structural coordinate system, what it learns on one task transfers to every task of the same shape — even ones that share not a single word.”

The one idea everything hangs on — E is the dual of F

A single coordinate system, four structural axes: partition · flow · role · scale.

F (RequiredStructure) — what structure the task requires, derived deterministically from the task's fingerprint. No LLM. "This is a divergent, retrieval task → it requires parallel gathering, a synthesizer, and depth ≈ 3."

E (EFTensor) — how far the plan actually built and run deviates from F, measured per axis, each in [0,1].

Error is measured in fingerprint space — E is the dual of F, same four axes. That's why improving a plan is literal coordinate descent (lock the worst axis, fix it, re-measure), and why learning transfers: error is invariant to phrasing, so a fix learned on one task applies to the whole structural class.

A second, content-quality tensor rides alongside — groundedness · relevance (generation-side RAGAS, computed mechanically). The final verdict is one uniform gate over all six axes: every axis under threshold → good; one axis barely over → mixed; else → poor. No weighted sums collapsing axes into a single number — that's a deliberate stance, not an oversight.

The run pipeline Orchestrator.run(task) — one public call, twelve steps

  1. RESEARCH.clarify()
    Raw intent → TaskFingerprint (the structural species) + TaskSpecifics (the actual content/constraints).CLAIM 1 · CAPTURE
  2. compute_required()
    → F, the RequiredStructure. Deterministic.
  3. Build next plan directive / descent loop
    Iteration 0: warm-start from a cached best-plan if one exists for this species; else the CEO cold-plans the DAG. Later iterations: if the directive names a deterministic move, apply it as a pure graph transform — no LLM.CLAIM 4 · REUSE
  4. Structural gate
    Force a verifier node if domain volatility requires it — a code guarantee, not a prompt suggestion.
  5. Secondary research pass
    Iteration 0 only; won't clobber a warm-started plan.
  6. KERNEL executes the DAG
    Flows upstream outputs into downstream nodes → ExecutionTrace.
  7. DELTA audits
    compute_ef() → E. Descent.step() picks the worst axis, emits a directive, and updates the incumbent under PRESERVE.CLAIM 3 · DESCEND
  8. Best-plan tracking
    Mirrors the descent's own incumbent decision. Loop breaks when the directive says "surface."
  9. Persist
    This species' trajectory + best plan write to the F-keyed store — feeds REUSE on the next task of this shape.
  10. CEO.compose()
    One coherent answer, in a single voice, from the winning DAG's work.
  11. Q-factor
    Groundedness + relevance on the delivered answer, folded into the final verdict.
  12. Reflection & return
    Periodic between-run reflection, persist, return RunResult.

The two learning loops — this is what makes it a system that learns, not just a pipeline. Intra-run (DESCEND): the directive loop repairs the plan within one call. Cross-run (REUSE): the store remembers the best plan per structural species; the next task of that shape starts warm.

Design decisions the “why” a smart CEO will probe

1. Unreduced tensor

Never collapse axes into a scalar. A weighted sum throws away which thing is wrong and lets a good axis mask a bad one. Instead: gates, banding, and rule-matching on the raw vector. Why: the directive can target the actual failure.

2. F is deterministic

No LLM in the measurement path. F is a pure function of the fingerprint; E is topology + embedding math. Why: the verdict is reproducible and defensible.

3. E is the dual of F (shared basis)

The single most important choice. It's what turns repair into coordinate descent and memory into transfer. Without it, you have two unrelated representations and no leverage.

4. PRESERVE — monotone incumbent, uphill rejection

A new plan becomes the delivered plan only if its worst axis is no worse than the best so far; otherwise it's rejected and descent keeps building from the incumbent. Why: one bad LLM re-roll can no longer poison the run — this is the headline guarantee.

5. Lexicographic incumbent — structure primary, content secondary

On a structural tie, Q breaks it — but Q can never justify regressing structure. Why: prevents a pretty-but-wrong-shaped answer from winning.

6. Deterministic graph operators, not “reconsider from first principles”

Which edit to attempt is a table lookup; the edit itself is a pure graph transform. The LLM is one competing move, not the whole mechanism. Why: the repair is inspectable and repeatable — and under PRESERVE, a bad LLM move just gets rejected.

7. Species as a controlled vocabulary

The fingerprint's shape string is drawn from a tiny fixed set of axis values, so exact string match = same structural class. Why: clean, non-arbitrary equivalence classes — the backbone of GENERALIZE and REUSE.

8. Modifier axes are not embedded

Complexity and domain volatility drive scalar behavior (depth budget, mandatory verifier) via direct gates, never similarity. Why: they'd pollute the structural key if embedded.

9. Structural gates as code guarantees, not prompt suggestions

A live-data task gets a verifier node — the planner's output is checked and patched if it skipped one. Why: “please verify” in a prompt is not a guarantee; code is.

10. Single-voice composition

The winning node's raw output is not the deliverable — the CEO composes one coherent answer, and never fails on this step (falls back to the raw answer). Why: a coherent entity, not a pile of node outputs.

11. Warm-start is initialization, not lookup

A reused plan is a starting point the descent can still repair. Why: transfer without brittleness.

Borrowed vs. original honest attribution reads as maturity

Adopted from outside

  • Sentence embeddings — all-MiniLM-L6-v2, 384-dim unit vectors. Every cosine in the system runs on this geometry.
  • LLM backend — vLLM (OpenAI-compatible), Qwen-family, self-hosted; the system is model-agnostic behind it.
  • RAGAS metrics — concept borrowed; the implementation is a mechanical, generation-side, de-LLM'd version.
  • Coordinate descent — borrowed framing that fits because E and F share a basis.
  • Warm-starting an optimizer — precisely what REUSE is.
  • Hysteresis — a one-iteration grace margin after a refine, so a just-fixed axis isn't re-flagged by noise.
  • Case-based reasoning — the store keeps concrete exemplars, not abstract rules.
  • Pareto dominance — legacy best-plan selector on non-EF paths, superseded by PRESERVE.
  • Centrality weighting — error contributions weighted by node in-degree.
  • KAIJU-inspired execution kernel — the DAG execution/context-flow design draws on that lineage.
  • Grounding via web search — today's retriever backend; deliberately swappable to a NANDA agent-directory backend.

Original to CEO-Delta

  • The E-is-the-dual-of-F coordinate system.
  • The PRESERVE monotone-descent guarantee.
  • The deterministic graph-operator repertoire + table-driven selection.
  • The structural-species key that gives transfer.
  • The behavioral-band role error — replacing a keyword-scan boolean with a text-derived profile against per-role bands.
Reference Methodology ◆ABOUT EVIDENCE.PY

Where these numbers come from

Every claim above is read from a JSON file this script writes — nothing on this page is invented or hand-tuned for the demo.

Running the battery

scripts/evidence.py prints a live, human-readable trace of all 5 claims, then writes scripts/evidence_results.json — the machine-readable payload this page renders. Re-run it any time to refresh the data; drop the resulting file onto this page to load it.

# full evidence battery — (re)writes scripts/evidence_results.json python3 -u scripts/evidence.py # one task, programmatically python3 -c "from ceo_delta import Orchestrator, Config; \ r = Orchestrator(Config(), workdir='.demo').run('Explain how a C compiler works'); \ print(r.report.verdict, r.report.ef_tensor)"

The richest live object is RunResult (returned by Orchestrator.run()): answer, report.verdict, report.ef_tensor, report.q_tensor, report.required_structure, iterations, ef_trace, ef_incumbent_trace (the monotone curve), ef_move_log, dag.nodes.

Reliability, claim by claim

  • CAPTURE, GENERALIZE, CONVERGE are deterministic or near-deterministic — safe to run live.
  • DESCEND asserts only architecturally-guaranteed facts: monotone incumbent, a deterministic op fired, a worse move rejected. It does not depend on lucky convergence — the magnitude of improvement can vary run to run, the monotonicity cannot. Lead with the invariant, not with which operator happened to fire.
  • REUSE uses a stable-domain task specifically so the cached plan is reproducible and the warm-start marker sticks.

Honest limitations

  • The partition axis is measured from execution outputs, so on similar-format-but-distinct-content parallel branches (e.g. flight vs. hotel retrievers) it can read a false redundancy. PRESERVE contains the damage — the bad merge is rejected — but the axis itself is a known imperfection; the principled fix is measuring partition from plan-time intent embeddings.
  • DESCEND's deterministic operators are stochastic to trigger — a given cold-plan may need an LLM move or a deterministic one. The guarantee holds every run; which operator fires does not.
  • CONVERGE is N=3, one mixed — illustrative of region-stability, not a statistical benchmark.
  • Grounding is a seam — the retrieval backend is swappable; built for a NANDA agent-directory backend, demoed with web search.
